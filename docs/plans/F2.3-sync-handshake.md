# F2.3 plan — Media sync handshake (no data written)

Status: **awaiting approval** (nothing below has been sent to the phone).

## Goal

Learn what the iPhone 5s (iOS 12.5.8) answers to a host's *HostInfo* and a *Media* sync request, and stop
there. No metadata, no files, no `MetadataSyncFinished`, no `AssetCompleted`.

## What we already know (F2.2)

- On connect the phone sends `InstalledAssets`, `AssetMetrics`, `SyncAllowed` (Music allowed, ManualSync on,
  no `GrappaSupportInfo`).
- Just opening the connection made the phone rewrite five `_MLDatabaseProperties` rows, including
  `MPDateLastSynced` (→ 2026-10-19 18:11:01 UTC). Songs, albums, playlists untouched (db-diff).
- DB sync bookkeeping today: `MLSyncClientLastSyncedRevision` 390, `MLSyncClientSyncAnchor` 0,
  `MLSyncClientGenerationID` −8769888188210626857.

## Exactly what will be sent

Two calls, after the phone's `SyncAllowed`:

### 1. `ATHostConnectionSendHostInfo(conn, HostInfo)`

| Key | Type | Value | Why |
|---|---|---|---|
| `Type` | string | `"iTunes"` | as published working client (S3) |
| `Version` | string | `"12.13.9.1"` | the iTunes version installed on this PC (Store build 12139.11001.62009.0); S3 sends `"13.7.0.161"` |
| `MacOSVersion` | string | `"Windows NT 10.0"` | as S3 (Apple's key name even on Windows) |
| `SyncHostName` | string | `"Miu Music"` | shows on the phone as the syncing computer |
| `LibraryID` | string | 16 upper-case hex chars, generated once and kept in Miu's settings (`atc_library_id`) | S3 uses a new UUID per run; a stable ID avoids looking like a new computer every time |
| `SyncedDataclasses` | array | `["Media"]` | music lives in the Media dataclass (`AssetMetrics.Media.Music`) |
| `SyncedAssetTypes` | array | `["Music"]` | phone's own asset-type vocabulary (`DisabledAssetTypes` lists Movie, TVEpisode, …) |
| `Wakeable` | bool | `false` | as S3 |

### 2. `ATHostConnectionSendSyncRequest(conn, dataclasses, anchors, HostInfo)`

- `dataclasses` = `["Media"]`
- `anchors` = `{}` (empty, as S3 — we don't yet know the anchor format; the phone's reply should show it)
- `HostInfo` = the same dictionary as above

## Steps

1. `device-backup` immediately before (read-only).
2. Connect, read until `SyncAllowed` (as F2.2). If it doesn't come within 10 s → stop.
3. Send HostInfo. Read and log for 3 s.
4. Send SyncRequest. Read and log until `ReadyForSync`, `SyncFailed`, or 15 s of silence.
5. **Stop**: `ATHostConnectionInvalidate` + `Release`. Nothing else is sent.
6. `device-backup` again → `db-diff` before/after → song count must still be 69.
7. You check the Music app on the phone (songs still there and playable).

Every message goes to `research/captures/` (gitignored); the app log gets names only.

## Expected and possible outcomes

- Phone replies `ReadyForSync` (params will show anchors/revisions it expects) → F2.4 can be designed.
- Phone replies `SyncFailed` with an error code → logged; we learn what it wants (e.g. a real anchor).
- The phone may briefly show "Syncing…" and then stop when we disconnect. Most likely leftovers: more sync
  bookkeeping updates (`MPDateLastSynced`, anchors) as already seen in F2.2.
- Worst case (unlikely, nothing is sent that describes the library): the phone treats the aborted session as a
  library change. Recovery: `device-restore <backup> --yes-write-to-phone` (only with your OK) or re-sync from
  3uTools.

## Tests first

- **Unit (CI):** `HostInfo` builder — exact keys and types above; `LibraryID` is 16 hex chars, generated once and
  read back from settings; `Media`/`Music` values.
- **Unit (CI):** handshake state machine fed with sanitized message fixtures (names only): refuses to send
  HostInfo before `SyncAllowed`; stops on `SyncFailed`; finishes on `ReadyForSync`; times out cleanly.
- **Machine (manual, gated):** `#[ignore]` *and* requires `MIU_ALLOW_SYNC_REQUEST=1`, so it can never run by
  accident (not even with `--include-ignored`).
